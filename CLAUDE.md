# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

KAM — Krajský analytický model. Hackathon Královéhradeckého kraje, tým Popojedem.
FastAPI backend (`backend/kam`), React + TypeScript + Vite frontend (`frontend/`), SQLite by default (PostgreSQL via `DATABASE_URL`). All UI copy, log messages and docstring-level vocabulary are Czech; keep it that way.

`npm run build` is `tsc -b && vite build`; `npm run lint` is the same type-check without emit. `python -m kam.ingest` takes individual steps (`geo`, `relief`, `catalog`, `eurostat`, `mos`, `khk`, `dotace`, `dokumenty`, `link`, `check`, `rag`, plus `check-new` and `admin`); each is idempotent and `all` runs them in dependency order. A full harvest takes minutes and hits live open-data endpoints — prefer a single step, or work against the existing `data/kam.db`. `relief` needs `geo` to have run first (it reads the projection out of `khk.json`); `eurostat` is the slow one at roughly ten minutes, because it verifies every one of ~8 900 datasets against the kraj.

Run the server through the Browser preview (`.claude/launch.json`, name `kam`, port 8000). The server serves `frontend/dist`; `/assets` is mounted at startup, so build the frontend before starting the server. `frontend` also has a Vite dev server on 5173 that proxies `/api` to 8000.

Both PowerShell scripts (`start.ps1`, `scripts/deploy.ps1`) must stay UTF-8 **with BOM**. Windows PowerShell 5.1 reads a BOM-less `.ps1` as ANSI, so Czech text turns to mojibake — and an em dash inside a double-quoted string decodes to a sequence containing a quote character, which ends the string early and throws a parse error pointing at a line that is perfectly fine. Validate a change with `[System.Management.Automation.PSParser]::Tokenize` rather than by running the script.

Neither Node nor Python is on PATH on the dev machine; bare `python` hits the Microsoft Store alias stub and fails with code 9009. Node: prefix `$env:PATH = "C:\Users\hushkys\AppData\Local\Programs\nodejs;" + $env:PATH`. Python 3.12 with all requirements installed is at `C:\Users\hushkys\AppData\Local\Programs\Python\Python312\python.exe` — that absolute path is what `.claude/launch.json` uses. (`start.ps1` would instead create a `.venv`; there isn't one here.)

## Architecture

One direction of flow, and each stage owns one job:

```
ingest/  → models.Observation (+ Dataset, Territory, Poi, Fact)
         → analytics/store.py  (the only reader of series; in-memory cache)
         → analytics/{trends,profile,risks,forecast,simulate,gaps}.py
         → api/{data,model,ai,reports}.py  (REST + SSE under /api)
         → frontend/src/lib/api.ts → pages/
```

- **`indicators.py` is the registry everything keys on.** Each `Ind` carries `pillar`, `polarity` (is higher better?), `agg` (how obce roll up into ORP/okres/kraj: `sum`, `wavg:<code>`, `wavg_pop`) and `origin` (the real producer, since ČSÚ MOS republishes other agencies' data). Derived ratios are declared here and computed per year in `store.py`, never stored.
- **`territory.py`** keys on RÚIAN codes and publisher IČO, the same identifiers NKOD and ČÚZK use. Every function takes a kraj code — KHK is the first deployment, not a hard-coded assumption.
- **`analytics/store.py` is the single definition of "value of indicator X in territory T in year Y."** Profiles, risks, forecasts and the AI tools all read through it. It caches series in memory; `store.reset()` / `risks.reset()` / `simulate.reset()` must be called together after an ingest. The `kam.ingest` CLI is a separate process and does *not* reset a running server's caches — restart the server after a manual ingest. Only the in-app scheduled refresh (`main.py::_scheduler`) resets them in place.
- **`ingest/relief.py` samples ČÚZK DMR 5G into the projection the SVG map already uses.** It reads `projection` out of `khk.json` and inverts it, so a grid vertex and an obec outline land on the same spot and the 3D map can paint the choropleth into a canvas and use it as a texture. Change `geo.py::Projector` and the relief has to be rebuilt.
- **`main.py` starts instantly on purpose.** Risk ranking, the simulation cache, the local-model warm-up, missing embeddings and the scheduled refresh all run on background threads (`_warm`, `_scheduler`), gated by `KAM_BACKGROUND`. Tests set it to `0`.
- **`db.py` has no migration tool.** `create_all()` plus `_ensure_columns()`, which only ever *adds* nullable/defaulted columns so an older snapshot keeps working. Renaming or retyping a column will silently do nothing — plan schema changes accordingly. SQLite runs in WAL so the API reads while an ingest writes.
- **Two settings stores, split by purpose.** `config.py` reads the environment (and `.env`) for things that differ per machine. `prefs.py` keeps server-side policy in the database — what may leave the machine (AI policy, retention, webhook target), validated against `DEFAULTS`/`CHOICES`/`RANGES` on every write, with SSRF checks on webhook hosts. API keys typed into the UI are Fernet-encrypted by `security.py` with a key in `data/secret.key`, never returned to the browser.

## Deployment

`DEPLOY.md` is the runbook; the shape is one container (`Dockerfile`) serving API + SPA, PostgreSQL over `DATABASE_URL`, and the SQLite snapshot pushed once with `scripts/migrate_to_postgres.py`. Three things that are easy to get wrong:

- **Firebase Hosting cannot run this app** — it serves static files only. The Firebase project is a GCP project, so the container goes to Cloud Run and `firebase.json` rewrites `**` to it. The rewrite must cover *everything*: serving `frontend/dist` from the Hosting CDN would put the app shell in front of the password.
- **The deployment is public — there is no login, and `test_aplikace_je_verejna` keeps it that way.** A QR code on a leaflet leads straight into the app. The consequence is that every write endpoint is public too: deleting a report, purging the log, changing server settings, spending the Gemini quota. If that ever needs closing, protect those endpoints specifically rather than putting a password back in front of the whole site — see the service-worker note in Frontend traps for what a site-wide HTTP Basic does to a PWA.
- **Start serveru přežije nedostupnou databázi a je to schválně.** `init_db()` vrací `bool`, ne výjimku: kontejner, který se kvůli mlčící databázi nerozběhne, je z venku k nerozeznání od smazané aplikace — a hlavně nejde nasadit ani oprava, protože Cloud Run novou revizi odmítne. Server tedy naběhne, `/api/health` vrátí `ok: false` i s důvodem a o obnovu se pokouší na pozadí (`db.zkus_obnovit`, nejvýš jednou za 30 s), takže se aplikace vrátí do provozu sama, jakmile databáze naskočí. Engine pro PostgreSQL má `connect_timeout` — bez něj libpq čeká na TCP timeout systému a nedostupná databáze požadavek nezhodí, ale zasekne.
- **Neon má na free tieru kvótu na přenesená data a warm-up ji pálí.** `_warm` při každém studeném startu natáhne celé série (`store.territories()`, `risks.ranking` přes všechny obce, `simulate.precompute()`); s `--min-instances 1` a několika nasazeními denně se limit vyčerpá a databáze začne odmítat spojení hláškou *„Your project has exceeded the data transfer quota"*. Projeví se to jako `The user-provided container failed to start` při nasazení — chyba, která svádí hledat problém v kódu, a v kódu není. Ověří se to jedním připojením k `DATABASE_URL` z `env.yaml`.
- `KAM_SECRET_KEY` moves the Fernet key off disk. Without it every redeploy generates a new key and the API keys stored in `model_provider` stop decrypting.

## Rules that keep the product honest

- Every number shown comes from the database; never type numbers into UI copy. Catalogue counts come from `api/data.py::dataset_counts`, where the headline is `verified` (`check_status == "ok"`) and `total` additionally includes rows whose link failed or is missing.
- `Observation` holds only published values. Forecasts and simulations are computed on read and never written back.
- `Dataset.loaded` is set only by `ingest/link.py` for datasets whose values a harvester really read. `Dataset.usage` states how every other dataset is used (`katalog`, `rag`, `pokryti`, `cerstvost`, `mapa`, `model`) — a harvested dataset with no honest use does not belong in the catalogue.
- **NKOD is effectively the whole Czech open-data landscape and the harvest of it is complete** — 375 of 376 publishers, and the only gaps are the daily series that `collapse_series` folds on purpose (STK alone registers 10 026 daily files as 10 026 datasets). Low regional counts are reality, not a bug: Středočeský kraj really publishes 22 datasets, and the krajs with thousands have an *IS DTM* catalogue. Do not go looking for a paging bug there again, and do not pad the count.
- `ingest/eurostat.py` is where the remaining headroom was: European regional statistics for NUTS3 `CZ052` and NUTS2 `CZ05`. Every candidate is **verified by asking for the kraj's own values** and kept only if the answer is non-empty (775 of 8 880). `region_code` is coverage, not publisher, so only the NUTS3 ones carry 86; `CZ05` covers three krajs and carries 0.
- `ingest/catalog.py` treats NKOD as authoritative and merges portal records onto it by normalised title within the same kraj *or* by download URL; a series of ≥ `SERIES_MIN` (30) daily slices collapses into one record.
- Two harvester rules that are easy to break and expensive to notice:
  - **Page NKOD over IRIs, never over result rows.** `_page_filter` takes an explicit batch from `_all_iris`. The metadata query drops datasets whose title is neither Czech nor untagged, so a full window can return short; the old "short page ⇒ last page" rule silently lost ~60 % of every publisher (NKOD reports 1 943 datasets for KHK, the catalogue held 800).
  - **Call `_ensure_source` before `_store`.** `Dataset.source_id` is a foreign key, so a harvester that stores rows for a brand-new source fails the whole insert at the end of a ten-minute run with nothing but `FOREIGN KEY constraint failed`.
  - **Build the duplicate index without the source being harvested** (`_titles_by_region(exclude)` / `_urls(exclude)`). A feed compared against its own previous harvest matches every row as a duplicate of itself, stores none, and `_store` then deletes the lot.
- `analytics/finance.py` answers "does the obec make or lose money" from the budget it already has (ČSÚ MOS republishing FIN 2-12 M): operating surplus = income − running costs, and investment cover = surplus / capital spending. The verdict is a rule with printed thresholds, and the page says outright that the budget cannot tell you what the money bought — no "return on investment" is computed anywhere.
- `analytics/umisteni.py` compares **where** an intervention should go, and it compares each obec against the median of obce **in its own size band**, never the kraj median. Per-1000 indicators otherwise always crown the biggest town: a village of 200 with three stops has 15 per 1000, Hradec Králové has 1.1. Bands come from `PASMA`; a band with fewer than `MIN_V_PASMU` obce falls back to the kraj median.
- `analytics/dotace.py` keeps three levels of certainty apart: the obec's actual receipts (MOS 200302, annual), what the kraj sent to its ORP (Data KHK, a 2021–2025 total — stored at year 2025 because that is how the kraj publishes it), and a **link directory** of grant providers. There is no machine-readable registry of open calls for Czech municipalities; the app says so instead of pretending, and never claims eligibility.
- **`analytics/plany.py` říká, co je doložitelné, a mlčí o zbytku.** Program rozvoje obce má v názvu období platnosti, takže se z něj dá spočítat, jestli dokument platí a kolik z období uplynulo. **Kolik z plánu je hotové, nezveřejňuje strojově čitelně nikdo** — registr, kde by u záměru stálo „realizováno", v Česku neexistuje a obce plnění vyhodnocují vlastními zprávami v PDF. „Stav plnění" proto znamená platnost dokumentu a uplynulý čas, vedle nich stojí kapitálové výdaje za tytéž roky z rozpočtu, a u nich je napsáno, že to není příčina a následek (`finance.py` říká totéž). Plný pruh tedy nikdy neznamená „splněno" — proto má prošlý plán utlumenou barvu (`tone-mute`), ne zelenou.
- **Odkaz do registru se skládá z IČO obce, nebo se nenabídne vůbec.** `plany.REGISTRY` drží celé adresy (MONITOR státní pokladny, registr smluv, ARES), ne základ s vyhledávacím formulářem — rozcestník po člověku chce práci, kterou za něj měla udělat aplikace. Obec bez spárovaného IČO (5 ze 448) dostane prázdný seznam; odkaz naslepo by mohl ukázat jinou obec. IČO plní `ingest/dokumenty.py` z ARESu a **porovnává `kodObce`, ne jméno**: stejnojmenných obcí jsou v Česku desítky.
- **Program rozvoje obce není povinný a na obcepro.cz je jich málo** — 26 ze 448 obcí kraje. „Chybí" tedy znamená „není v registru MMR", ne „obec nic neplánuje", a stránka to říká slovem. Nedoplňovat to odhadem a nehledat v tom chybu sklizně. Objem dokumentů nese **evidence ÚPD kraje** (`up.khk.cz/upd/seznam`, 2 887 záznamů proti 30 z obcepro): územní plán a každá jeho změna s datem vydání a vlastní stránkou. Sloupec *Archivováno* je jediná strojová informace o tom, že dokument nahradil jiný — platný je proto nejnovější **nearchivovaný** záznam, ne prostě nejnovější.
- **Mazací rozsah sklizně je celý kraj, ne jmenný slovník.** `_obce_kraje` vyhazuje stejnojmenné obce, ale ukládat do nich umíme (ÚPD se páruje na kód RÚIAN) — a co se uloží a nesmaže, se při druhém běhu zdvojí. Bylo to 15 dokumentů osmi obcí na každou sklizeň. Ověřuje se to dvěma běhy za sebou a porovnáním počtu řádků, ne pohledem do logu.
- **Řádky ÚPD se párují na kód RÚIAN, kde je** (`MAP=_kod` v odkazu na mapu, asi dvě pětiny řádků), jinak na normalizované jméno. Se samotným jménem zůstávalo nepřiřazených 30 dokumentů, s kódem 15 — a u stejnojmenných obcí je jméno prostě špatná odpověď.
- **Stránkování obcepro se hledá regulárním výrazem `page=(\d+)` bez `[?&]` před ním.** V HTML je ampersand zapsaný jako `&amp;`, takže znak před parametrem je středník; přísnější vzor našel jen stránku 1 a sklidil desetinu dokumentů, aniž by cokoli selhalo.
- Assumptions in `analytics/simulate.py::ASSUMPTIONS` carry a value and a reason and are overridable per request.
- **Každá stránka aplikace má svůj dokument v `ai/knowledge.py`.** Chyběly čtyři (Plány, Hospodaření, Dotace, Statistiky), takže je asistent neuměl popsat a `/api/search` je nenašel podle metodiky. Dokument s předponou `metoda-` se navíc objeví v seznamu metodik na stránce Data (`/api/methods` filtruje podle předpony id), `stranka-` ne — to je záměr. Po úpravě je potřeba přestavět index (`python -m kam.ingest rag`), jinak se změna nikde neprojeví.
- The LLM never computes numbers: `ai/tools.py` produces labelled briefs (FAKT/TREND/MODEL/SCÉNÁŘ) that the model explains.
- **Podklad pro asistenta nese i `DOKUMENTY` a hned za nimi řádek `POZOR`**, že uplynulý čas období není splněný plán. Bez té věty model z „období uplynulo ze 100 %" udělá „plán je splněný" — je to nejpřirozenější chybný závěr, který nad těmi daty jde udělat, a nikdo ho nezveřejňuje. V úsporném podkladu pro lokální model se řádky se stavem `chybi` vynechávají: prefill je tam to pomalé a dvě zprávy o tom, co obec nemá, za to nestojí.
- `trends.py` is deliberately robust statistics (Theil–Sen, Mann–Kendall, MAD z-scores) because small-obec counts are never normal; `risks.py` lowers confidence for small populations and short series.
- Citizens' reports (`crowd.py`) cluster into formal submissions but never feed back into `Observation`. They can be deleted — `crowd.smaz` for one, `crowd.uklid` for a batch — and `uklid` with no filter deletes nothing on purpose, because a single unparameterised call that wipes the table is a trap, not a feature. Deleting a delivered submission loses the app's only record of what was sent to the kraj, so both write a line to the operations log with the reference and the count, never the text.
- **`logs.py` is the only writer into `audit_log`.** What goes in `detail` is counts, identifiers and reasons — never report text, chat queries or IP addresses, because the log has its own retention and must not become a second copy of the data it describes. `logs.zapis` swallows its own errors: a log that breaks the operation it is recording has its priorities backwards. Retention is in `prefs` under `provoz`, and **0 means keep forever** — `podnety_dni` defaults to 0 because automatically discarding what people submitted has to be a deliberate choice, and only delivered submissions are ever eligible.
- `main.py::_udrzba` runs the retention daily. Doing it once at startup (which is all `assistant.purge_old()` used to get) is not retention: the container runs for weeks and the tables grow the whole time.

## Veřejné API

- **`api/verejne.py` (`/api/v1`) je jiná vrstva než zbytek `/api`.** Ten obsluhuje tuhle aplikaci a vrací hotové profily a výhledy; `/api/v1` vydává samotná data, aby si je kdokoli stáhl a udělal si s nimi své. Index na `/api/v1` je samopopisný — `cesty` i `priklady` jsou funkční adresy, takže API jde použít bez dokumentace.
- **CORS je schválně jen na `/api/v1`** (nastavuje ho middleware `headers` v `main.py`). Právě tohle má kdokoli volat ze svého webu; do zbytku API cizí stránce nic není a `test_v1_ma_cors_a_zbytek_api_ne` to hlídá.
- **CSV a NDJSON se streamují přes `yield_per` a nemají strop**, JSON stránkuje po `limit` a vrací `dalsi`. CSV začíná BOM, jinak Excel na Windows přečte diakritiku jako paskvil. Ke každé hodnotě patří `puvodce` z `Indicator.origin` — číslo bez původu je tvrzení, ne data.
- **`/api/v1/dokumenty` vydává povinně zveřejňované dokumenty obcí** — programy rozvoje i územně plánovací dokumentaci, u každého odkaz na originál i na registr, ze kterého je. `od`/`do` filtrují podle **období platnosti**, ne podle data zveřejnění; horní mez schválně vyřazuje `do == 0`, protože nula tu znamená „dokument období nemá" (tak je uložená ÚPD), ne „platí do roku nula". `stav` vyplňuje jen ÚPD — jinde o platnosti nikdo strojově čitelně nic neříká a prázdno je poctivější než dopočítaná domněnka.
- `scripts/kam.py` je klient API a **záměrně nemá závislosti mimo standardní knihovnu**: nástroj, kvůli kterému si musí úřad nejdřív něco nainstalovat, se nepoužije. Míří na veřejné nasazení, vlastní instance se zadá přes `--server`.

## AI notes

- Chat is one pipeline in `ai/assistant.py`: guard → commands → route → tools + retrieval → model, streamed as SSE (`meta`, `action`, `token`, `done`).
- App commands (`ai/commands.py`) run without a model and are validated against an allowlist; the model may emit `AKCE: {...}` lines, parsed and validated the same way.
- `ai/router.py` decides intent and tier from keyword evidence on unaccented text in microseconds; the model-based refinement is optional and falls back to the heuristic on any failure.
- `ai/rag.py` fuses BM25 (unaccented, prefix-stemmed for Czech inflection) with local embeddings via RRF. Vectors are built in the background; BM25 answers alone until they exist.
- `ai/guard.py` is three layers: input screen, retrieved context fenced as untrusted evidence, and a canary token in the system prompt that voids an answer if it leaks.
- Local servers get `reasoning_effort: "none"`: Gemma 4 otherwise spends its whole budget in `reasoning_content` and returns nothing.
- The local tier gets a compact brief (prefill is the slow part on Gemma 4 E4B).
- With no model reachable, the assistant returns the tool brief as a grounded fallback.
- The routed tier is tried first, then the other one, then the brief; the `done` SSE event carries the model that actually answered, because `meta` is emitted before the attempt and would otherwise credit the wrong one.
- Under the `local_only` data policy `cloud` is set to `None` in `assistant.py` before the router runs — the classification call would otherwise send the query to the cloud that the policy forbids.
- `GEMINI_API_KEY` in `.env` is enough: `seed_defaults` adopts the keyless placeholder row it seeded on a first run. Gemini answers 429/503 "high demand" on the shared tier, so `_gemini_stream` retries twice with a short backoff; 3.x flash models burn the whole output budget thinking unless `thinkingConfig.thinkingBudget` is 0.

## Tests

`backend/tests/conftest.py` sets `KAM_DATA_DIR`, `KAM_BACKGROUND=0`, `DATABASE_URL` and an unreachable `LOCAL_LLM_BASE_URL` *before* importing `kam`, because `config.settings` and the SQLAlchemy engine are created at import time. Anything that imports `kam` earlier breaks the isolation.

The session-scoped `synthetic_db` fixture builds a small fake kraj whose shape triggers known behaviour: Horní Testov is ageing, shrinking, losing people to migration and has no sewerage; Velké Město is stable but carries a one-off 2020 death spike. Assertions lean on those properties — extend the fixture rather than reshaping the existing towns.

Frontend tests are a single `src/lib/lib.test.ts` covering formatting, prefs, the router matcher and chart/map scales.

## Frontend traps

- A sparkline is stretched (`preserveAspectRatio="none"`) and stroked in screen space (`non-scaling-stroke`). Do not reveal its line with `stroke-dasharray` + `pathLength`: the browser measures the dash pattern in one space and the path in the other, so only about half the line ever draws and the result looks like a broken chart with the end dot floating away. Use the clip-rect wipe that the area fill already uses.
- No UI, chart or map libraries: `components/charts.tsx` and `components/maps.tsx` draw SVG by hand, `lib/router.tsx` is a ~120-line History API router, styles are four hand-written files in `src/styles/` (`base`, `components`, `hook`, `pages` — in that import order).
- Do not put `view-transition-name` on fixed elements that carry `backdrop-filter` (navbar, spodní lišta): it produced black frames after scrolling.
- Do not use `background-attachment: fixed`; the ambient glow is `body::before`.
- **`body` má `overflow-x: clip`, ne `hidden`.** S `hidden` se druhá osa počítá jako `auto`, `body` se stane rolovacím kontejnerem a `position: sticky` uvnitř se přestane chytat obrazovky — připíchnutá dějství na úvodní stránce by tiše přestala fungovat a nikde by to nic neohlásilo. `clip` ořezává stejně a kontejner nedělá.
- **Vjezd potřebuje dorovnání po prvním vykreslení.** `IntersectionObserver` hlásí *změnu* protnutí, jenže rozvržení se na úvodní stránce ustaluje ještě po něm (dotečou data z API, doběhne písmo, mapa si dopočítá výšku). Prvek, který je přitom celou dobu na obrazovce, se nemusí dočkat ani jedné zprávy a zůstane na `opacity: 0` — na telefonu z toho byla obrovská prázdná mezera pod tlačítky, kde měla být mapa. `useVjezdy` proto po observeru ještě sám projde, co je vidět, a zopakuje to po 400 ms a na `load`. Prah je z téhož důvodu na nule: původních „18 % prvku“ se u vysokého bloku počítalo z jeho vlastní výšky, takže se musel vysunout o 131 px, než vůbec naskočil.
- **Pozor na `getComputedStyle().opacity` v náhledovém panelu.** Vrací tam `0` i pro prvky, které jsou evidentně vykreslené (hlásí to i `#main`), takže se podle něj nedá ověřovat viditelnost — ověřuje se přítomnost třídy `je-videt` a snímek obrazovky.
- **`KrajVizual` jsou tři vrstvy nad sebou** — mapa, hřeben vývoje, popisky — a pod kurzorem se každá **posouvá** jinou rychlostí. Posun v rovině, **ne otáčení**: `perspective` + `preserve-3d` + `rotate` udělá z celé scény jednu texturu, kterou prohlížeč rasterizuje v jednom měřítku a pak škáluje, takže na displeji s vyšší hustotou pixelů byla mapa viditelně rozmazaná. Různá rychlost vrstev udělá hloubku skoro stejně dobře a kresba zůstane ostrá. Vrstvy jsou tři samostatná `<svg>` se stejným `viewBox`, protože se musí hýbat samostatně; posun je ozdoba, takže odpadá pod `data-motion="reduce"` i tam, kde není jemný ukazatel.

Čtyři karty vedle sebe vypadaly jako ceník a zahodily jedinou strukturu, kterou tým má — dvě oblasti a v každé někdo, kdo ji vede. Řádek to řekne sám: portrét, jméno, čím se zabývá, vpravo oblast. Portréty (`Avatars.tsx`) jsou jeden systém: stejná hlava, stejné světlo zleva, stejné proporce, a rozdíl dělá jen silueta vlasů, doplněk a barva. **Vousy se kreslí pod obličej, brýle nad něj** — plnovous přes ústa udělá z portrétu škrabošku.
- **Ozdoba vytažená za okraj sekce rozšíří rolovací plochu.** Záře pod sekcí měla kdysi zápornou boční `inset`, aby přesahovala; `scrollWidth` tím narostl o 181 px a stránkou šlo hýbat do strany, přestože `overflow-x: clip` nic nezobrazil. Ozdoba proto drží šířku rodiče a rozpětí jí dělá gradient. Pozná se to měřením `document.documentElement.scrollWidth - innerWidth` na několika pozicích rolování, ne pohledem.

Hýbe tím **přechod**, ne JavaScript — cílová poloha je jedna proměnná `--c`, pořadí zleva `--i`. Výška políčka je `--od-h: 1.08em`, ne `1em`: číslice nemají dolní dotažnici, ale font je přetahuje přes účaří a v přesně jednom em se ořežou shora. Čtečka dostane hotové číslo ve `visually-hidden`, protože rozsypané číslice by přečetla po jedné.

Výchozí motiv je `system` (úřad pracuje na světlém Windows, doma se sedí u tmavého). „Vypnout animace“ je v Nastavení dvakrát (Vzhled i Přístupnost) a je to schválně **jedna** předvolba `reduceMotion`. `transparency` dnes znamená jen průsvitnou horní lištu a spodní lištu; sklo jinde není. `nav` (`full` | `compact`) nahradila `dock` a `dockLabels` — stará hodnota se v úložišti ignoruje a asistent zná klíč `nav` (`ai/commands.py`, `ai/prompts.py`).

Při tahu jedou obě stránky 1 : 1 jako list papíru a po dojezdu se pod náhledem vymění za skutečnou — táž komponenta se stejnými daty, takže výměna není vidět. Pět věcí, které se snadno pokazí: (1) náhled žije pod vlastní adresou přes `NahledLokace` (`lib/router.tsx`) — cesta cíle a **prázdný dotaz**, protože navigace z panelu dotaz nepřenáší; jinak by po přechodu stránka vypadala jinak než v náhledu. (2) Stránka, která v efektu zapisuje do adresy (`setQuery` v `Data.tsx` a `Scenarios.tsx`), to v náhledu dělat nesmí — přepsala by adresu stránky, na které člověk ve skutečnosti je; hlídá to `useNahled()`. Nová stránka se stejným vzorem musí přidat totéž. (3) Stránka otevřená gestem nesmí znovu naskakovat: `navigate(kam, { gesto: true })` dá na `<html>` `data-prechod="gesto"`, které nájezdové animace srazí na nulu, a značka zmizí za 2,6 s — dřív ne, jinak by se animace rozběhly od půlky; každá jiná navigace ji ruší hned. (4) Dojezd má pojistku časovačem, protože `finished` na skryté záložce nedoběhne a stránka by zůstala odsunutá. (5) Vodorovný tah patří prvku, který si o něj řekl (`touch-action` bez vodorovné složky, vodorovné rolování, `data-gesto="ne"`); pod `data-motion="reduce"` gesto zůstává, jen bez náhledu a dojezdu.

- **Hlavička modulu (`.sc-hook`) je pracovní panel, ne plakát:** vlevo název, věta a akce, vpravo jeden rámeček s grafem, nahoře pruh v barvě modulu. Odstín posílá `hookTema(modul)` jako tři surové barvy (`--hs` světlejší, `--ht` sytější, `--hp` bledá) a styl podle motivu rozhodne, co nese čáru: na světlém podkladu sytá, na tmavém světlá. Třetí barva `--h3` je na světlém střední tón — bledá na bílé zmizí (popisek „+53 %“ v Přehledu). Treemap v hlavičce Dat bere světlejší odstín v obou motivech, protože na něm leží tmavý popis. Nájezd je **jeden pro všechny moduly** (prolnutí o pár pixelů); vlastní choreografie po modulech a nadpis po slovech tu byly a odešly — odlišení stránek nese barva, ne pohyb. `NadpisHooku` dělí nadpis dál na slova, ta ale stojí.

Its curves are the real baseline/scenario arrays; with no result yet the pane stays empty rather than showing an invented shape. **Kreslí se rozdíl, ne jen dvě čáry**: příčky mezi cestami rok po roce a pod nimi pruh, kde je ten rozdíl vynesený od nuly (nula dole, dokud jdou všechny roky jedním směrem, jinak doprostřed). Předchozí verze kreslila každou řadu na vlastní výšku a tvary vedle sebe nešly porovnat; to je ta chyba, ke které se nemá vracet.
- **Hook Mapy kreslí skutečné hranice ve třech přiblíženích** (`/geo/cz` a `/geo/khk`, které si stránka tahá stejně — jde o sdílenou cache, ne o druhé stažení). Obálky se počítají rovnou z `d` řetězců regulárním výrazem, protože cesty z `geo.py` mají jen `M x,y L x,y … Z` v absolutních souřadnicích; `getBBox()` by musel čekat na DOM. - The mascot (`components/WordmarkHop.tsx` + `mascot-engine.ts`) is drawn by a `requestAnimationFrame` loop, not by keyframes, and the loop owns the `d` attribute and the transforms. Do not add CSS animations to `.wordmark.hop` — they would fight the loop and the mascot would move in two places at once. Three things that are easy to undo by accident: the body is a four-Bézier blob whose four radii move independently (a `scale()` can only make an ellipse, which is exactly the look this replaced); every height in the choreography is the **surface the mascot stands on**, and the centre follows as `surface − rBot`, which is what keeps it on top of a letter instead of inside it however it squashes; and it lands on the M's **right** shoulder, because the M dips to y = 57 between its two peaks and a walk along y = 0 would cross thin air.
- **Maskot nápis odtlačí na střed jen s `WordmarkHop vycentrovat`** (`POSUN_STRED` v `mascot-engine.ts`, fáze `tlaci`). Úvodní stránka má nápis zarovnaný doleva na každé šířce, takže ho nepoužívá; `viewBox` nápisu má vlevo 70 z 430 jednotek volných (tudy maskot přibíhá) a `hook.css` je vrací záporným okrajem, aby K lícovalo s textem. Posun drží smyčka jako `transform` na obalovém `<g>`; živá varianta proto **nesmí** nést třídu `ms-stred`, protože CSS `transform` atribut přebije a maskot by skončil na dvou místech naráz.
- **`KhkMap` zooms by moving the `viewBox`, not by a `transform`** — paths stay crisp and the outlines keep their pixel width through `vector-effect: non-scaling-stroke`. Every change goes through the state updater form: two taps on the plus button inside one frame would otherwise both compute from the same starting view and the second would do nothing. Gestures are split so they never fight the page: at 1x one finger scrolls (`touch-action: pan-y`) and two fingers zoom; once zoomed, one finger pans, because by then the person is driving the map on purpose. A drag must not end in a selection, so a pointer that moved past the threshold swallows the following click in the capture phase. ORP labels are in user units and are divided by the zoom, or they inflate.
- `components/Relief3D.tsx` is the only three.js in the app and is `React.lazy`-loaded from `MapPage`; it is a 510 kB chunk against a 449 kB app. The obec colours are a canvas texture, never per-vertex attributes, and a second canvas painted with index colours turns a raycast hit into an obec in one `getImageData`. Two things bite: exaggeration above ~8× turns a 300 m grid cell into a spike and the landscape stops being recognisable (the slider stops at 12), and OrbitControls claims every touch — on a coarse pointer the view starts locked (`touch-action: pan-y`, `controls.enabled = false`) so the page can still be scrolled past it.
- **Šířka obsahu je plynulá a počítá se z plochy vedle panelu.** `--maxw: clamp(1180px, calc((100vw - var(--side-w)) * .94), 3200px)` a `.page` má `margin-left: var(--side-w)` a `padding-inline: max(var(--pad), (100% - var(--side-w) - var(--maxw)) / 2)` — procenta u `padding` se berou z rodiče, takže se obsah drží uprostřed zbylé plochy od notebooku po 4K. S plochou roste i rytmus (`--gap`, `--card-pad` mají kroky na 1800 a 2600 px) a na 4K bez systémového zvětšení `html { font-size }` o 6 %. Vlastní hustota `compact` má vyšší specifičnost, takže si ji kroky nepřebijí.

- **Rozvržení uvnitř stránky se láme podle šířky obsahu, ne okna: `.page` je kontejner `stranka`** a mřížka (`span-*`), hlavička modulu, podněty, nastavení, plány i profil mají `@container stranka (…)`. - README screenshots are produced by `scripts/screenshots.py` against a running app (headless Chrome + Pillow). It forces `prefers-reduced-motion`, which the app answers by collapsing entrance animations to nothing — otherwise the shot lands mid-fade and the cards come out half-transparent. The hook page is the exception: it keeps motion so the mascot finishes its hop. **Adresa s `?t=` musí mířit na obec z prvních řádků seznamu**: `?t=` řádek otevře a najede na něj, a headless prohlížeč po dlouhém `scrollIntoView` vyfotí prázdnou plochu — v opravdovém okně je stránka v pořádku, v `docs/screenshots/plany.png` byl černý obdélník. Delší `--virtual-time-budget` s tím nepohne. Po přegenerování se vyplatí projet snímky přes počet barev; prázdný má jednu.
- **`.chat-uvod` musí mít `align-content: safe end`, ne `end`.** V nízkém okně se obsah nevejde a obyčejné `end` ho vystrčí nahoru **ven z boxu** — pozdrav pak leží přes hlavičku „Asistent KAM". `safe` se v ten okamžik chová jako `start`; zbytek dořeší `overflow: hidden` a `@container` pravidla, která uvítání svlékají odshora (nejdřív odstavec, pak jiskra, pak návrhy), ať v každé výšce zbyde aspoň pole.
- **Pruh „bez spojení" a šuplík asistenta o sobě musí vědět.** `Offline` píše `data-spojeni="pryc"` na `<html>` a šuplík pod pruhem povolí; bez toho na užším okně zajel pruh pod jeho roh. Pruh má vyšší `z-index` než šuplík i dock — hlášení o stavu spojení, které je zpola schované pod jinou vrstvou, vypadá jako chyba vykreslení.
- **Asistent se neotevírá jako chat, ale jako pole.** `Chat` má `data-stav="uvod" | "chat"`: dokud není zpráva, je uprostřed jen pozdrav, jedna věta a pole — **žádné návrhy otázek**. Byly tam a přidávaly čtvrt obrazovky textu, který nikdo nečte a který v šuplíku na telefonu vytlačil pozdrav z rámu. Vzduch nad polem i pod ním je vlastní prvek (`.chat-vzduch-horni` / `.chat-vzduch`), takže se pozdrav s polem drží uprostřed, ale nikdy si neukousnou z jeho výšky. Po odeslání pole **sjede** dolů — klasický FLIP, pozice se bere těsně před odesláním a rozdíl se přehraje pozpátku. Musí to být tentýž prvek, jinak by zmizel rozepsaný text i kurzor; proto se formulář nikdy nepřemísťuje v DOMu, mění se jen rozvržení kolem něj.
- `lib/api.ts` wraps fetch with timeouts and a stale-while-revalidate cache; call `invalidate(prefix)` after a mutation instead of reloading.
- **If the app ever goes back behind a password, `sw.js` must stop answering navigations.** Only a real browser navigation raises the login dialog; anything returned through `respondWith` does not, so the browser paints a bare `401 Unauthorized` and the whole site becomes unreachable — this happened once, when HTTP Basic and the service worker were live at the same time. While the app is public, network-first with the cached shell as the fallback is correct and is what the worker does. A user stuck on a bad worker gets out with a forced reload (Ctrl+Shift+R), which bypasses it for that navigation.
- **`public/sw.js` is hand-written and has no build-time precache list** — asset names carry a content hash, so a generated list would go stale the first time someone forgot to regenerate it. Everything is cached at runtime instead: navigations network-first with a 4 s cap (a mobile connection that accepts and then goes quiet is worse than none), `/assets/*` cache-first because the hash makes them immutable, `/api/*` GET network-first with the last known answer as the fallback. `/api/health` is skipped so the platform probe never reads a cached "ok", and non-GET is not intercepted at all, which is what keeps the assistant's SSE stream (a POST to `/api/chat`) out of it.
- **The offline banner is driven by the service worker, not `navigator.onLine`.** A phone on wifi with an unreachable server still reports `onLine === true`; the worker posts `{kam: "offline"}` whenever it serves a cached answer, so the app admits the numbers are from the last visit. Serving yesterday as today is exactly what the product criticises elsewhere.
- `main.py` serves `sw.js` with `Cache-Control: no-cache` while every other static file gets a day — it is the file that announces new versions of all the others. A new worker waits and the app offers a toast; it never takes over mid-session, because swapping the bundle under a half-built scenario is worse than the old version.
- `public/theme-init.js` also sets `<meta name="theme-color">`, mirroring `prefs.apply()` — without it the status bar of the installed app stays dark until React boots.
